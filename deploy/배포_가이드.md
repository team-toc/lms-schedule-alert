서버: **AWS EC2 `ubuntu@54.116.173.97`** (= toc-schedule.kro.kr)

## 1. 서버의 옛 백엔드 먼저 정리  ⚠️ 배포 전 필수

4000번 포트를 지언이 만든 옛 `toc-backend.service`가 물고 있으면 새 서비스가 못 뜬다.

```bash
ssh -i ~/.ssh/lms-schedule-alert.pem ubuntu@54.116.173.97
sudo systemctl stop toc-backend 2>/dev/null; sudo systemctl disable toc-backend 2>/dev/null
sudo ss -ltnp | grep :4000 || echo "4000 비었음 OK"
exit
```

## 4. 서버 안으로 들어가서 설치

```bash
ssh -i ~/.ssh/lms-schedule-alert.pem ubuntu@54.116.173.97
APP=/srv/lms-schedule-alert

# 백엔드 교체 (옛 버전은 backend.old 로 백업)
sudo mkdir -p $APP && sudo chown -R ubuntu:ubuntu $APP
rm -rf $APP/backend.new && mkdir -p $APP/backend.new && cp -r /tmp/lsa/backend/* $APP/backend.new/
[ -f $APP/backend/.env ] && cp $APP/backend/.env $APP/backend.new/.env   # 기존 .env 보존
rm -rf $APP/backend.old; [ -d $APP/backend ] && mv $APP/backend $APP/backend.old
mv $APP/backend.new $APP/backend
cd $APP/backend && npm ci --omit=dev
```

## 5. .env 설정  (최초 1회 / 담당: 영민)

`$APP/backend/.env` 가 **없으면** 새로 만든다. 이미 있으면 **VAPID 3줄만 확인**.

### 5-a. DB·기본값 (최초 1회)
```bash
cd /srv/lms-schedule-alert/backend
DBPW=$(openssl rand -hex 16); SS=$(openssl rand -hex 32)
sudo mariadb <<SQL
CREATE DATABASE IF NOT EXISTS lms_schedule_alert CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'lsa'@'localhost' IDENTIFIED BY '$DBPW';
ALTER USER 'lsa'@'localhost' IDENTIFIED BY '$DBPW';
GRANT ALL ON lms_schedule_alert.* TO 'lsa'@'localhost';
FLUSH PRIVILEGES;
SQL
cat > .env <<ENV
PORT=4000
NODE_ENV=production
TRUST_PROXY=true
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=lsa
DB_PASSWORD=$DBPW
DB_NAME=lms_schedule_alert
TEST_DB_NAME=lms_schedule_alert_test
SESSION_SECRET=$SS
FRONTEND_URL=https://toc-schedule.kro.kr
KAKAO_REST_API_KEY=not-set
KAKAO_CLIENT_SECRET=not-set
KAKAO_REDIRECT_URI=https://toc-schedule.kro.kr/api/auth/kakao/callback
GOOGLE_CLIENT_ID=not-set
GOOGLE_CLIENT_SECRET=not-set
GOOGLE_REDIRECT_URI=https://toc-schedule.kro.kr/api/auth/google/callback
ENV
chmod 600 .env
```
> 카카오·구글 로그인 쓰려면 `not-set` 자리에 콘솔에서 받은 실제 키를 채운다.

### 5-b. VAPID 키  ⚠️ 이게 없으면 서버가 안 켜짐 (담당: 영민)
```bash
cd /srv/lms-schedule-alert/backend
# .env 에 VAPID 가 이미 있으면 건너뛴다 (키 바꾸면 기존 푸시 구독 다 무효)
grep -q VAPID_PUBLIC_KEY .env || npx web-push generate-vapid-keys
```
출력된 Public / Private Key 를 `.env` **맨 끝에 추가**:
```
VAPID_PUBLIC_KEY=<출력된 Public Key>
VAPID_PRIVATE_KEY=<출력된 Private Key>
VAPID_SUBJECT=mailto:admin@toc-schedule.kro.kr
```
> 키 **값은 캡처·공유 금지**. 한 번 만들면 계속 쓴다.

## 7. 백엔드 서비스 등록·재시작 (최초 1회 등록, 이후 restart만)

```bash
sudo tee /etc/systemd/system/lms-backend.service >/dev/null <<UNIT
[Unit]
Description=lms-schedule-alert backend
After=network.target mariadb.service
[Service]
User=ubuntu
WorkingDirectory=/srv/lms-schedule-alert/backend
ExecStart=/usr/bin/node src/index.js
Restart=always
RestartSec=3
[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload
sudo systemctl enable lms-backend
sudo systemctl restart lms-backend
sleep 2 && curl -sf http://127.0.0.1:4000/api/health && echo "  backend 4000 OK"
```
> 안 뜨면: `sudo journalctl -u lms-backend -n 30 --no-pager` (대개 .env VAPID/DB 문제)

## 8. 프론트(정적파일) nginx 자리에 복사

```bash
# nginx 가 toc-schedule.kro.kr 에 주는 root 폴더 찾기
CONF=$(grep -l toc-schedule.kro.kr /etc/nginx/sites-enabled/* | head -1)
ROOT=$(grep -m1 -E '^\s*root ' "$CONF" | awk '{print $2}' | tr -d ';')
echo "root = $ROOT"
sudo rm -rf "$ROOT.old"; [ -d "$ROOT" ] && sudo cp -r "$ROOT" "$ROOT.old"   # 백업
sudo rm -rf "$ROOT"/* && sudo cp -r /tmp/lsa/dist/* "$ROOT"/ && sudo chmod -R a+rX "$ROOT"
```

### `/api` 프록시 (최초 1회만, 이미 있으면 건너뜀)
```bash
grep -q 'location /api' "$CONF" && echo "이미 있음 — 건너뜀" || echo "아래 블록 추가 필요"
```
없으면 `sudo nano "$CONF"` 로 `server { ... }` 안, `location / {` **위**에 추가:
```nginx
location /api/ {
    proxy_pass http://127.0.0.1:4000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```
```bash
sudo nginx -t && sudo systemctl reload nginx   # 문법 OK 확인 후 반영
exit
```
